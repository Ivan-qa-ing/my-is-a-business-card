Обо мне

Инженер по тестированию. Для меня качество продукта и предсказуемость релизов — приоритет. Работаю системно: анализ требований → тест-дизайн → проверки → логи и метрики → ретест. Спокойно держу дедлайны, люблю копать в логи и API, чтобы найти корневую причину, а не симптом.

Более 15 лет в футболе научили дисциплине и выдержке. В конфликтах фокусируюсь на решении, а не на споре. Планирую расти в сторону API-тестирования и автоматизации.

Честно об опыте: на реальных проектах (Лабиринт, Auto.ae) тестировал веб-приложения и REST API. Мобильные приложения (push, диплинки, debug-сборки через Android Studio, Firebase) и автоматизация (Cypress, Pytest, GitHub Actions) — опыт на учебном production-like тренажёре QA Studio. Готов углубляться в эти направления на реальных задачах.

Кейсы

Лабиринт — QA Engineer

E-commerce · Web + API

Задача: обеспечить стабильность релизов интернет-магазина, покрыть E2E-сценарии покупки и интеграции с платёжным шлюзом.

  • Ручное тестирование фронтенда и REST API: функционал, регресс, smoke, sanity.
  • E2E-сценарий: поиск → корзина → оформление → оплата.
  • API-проверки в Postman (скрипты, Collection Runner / Newman), сверка со Swagger.
  • SQL-запросы в PostgreSQL для локализации дефектов.
  • Логи в Kibana / Sentry, мониторинг 4xx/5xx в Grafana после релиза.

Результат: инициировал и внедрил ревью тест-кейсов — выросло покрытие, ускорился процесс тестирования; снизилось количество правок на этапе тестирования за счёт анализа требований и макетов до разработки.

Auto.ae — Intern QA Engineer

Marketplace · Web

Задача: с нуля выстроить тестовую документацию кабинета дилера и покрыть ключевые сценарии.

  • Разработал чек-листы (Miro) и тест-кейсы (Test IT) — покрытие ~90% ключевых сценариев.
  • Кросс-браузерное тестирование (Chrome, Firefox), систематизация проверок.
  • API-проверки через Swagger и Postman: позитив, негатив, граничные значения.
  • Нашёл 45 функциональных дефектов и 97 проблем вёрстки — детализированные баг-репорты.
  • Ревью баг-репортов других тестировщиков, стандартизация формата.

Результат: время регресса −25–30%, браузеро-зависимые баги в проде −~40%, инциденты по API −~20%, возвраты баг-репортов «на доработку» −15–20%.

QA Studio — учебный production-like проект

Microservices · API · Mobile · Automation

Задача: пройти полный цикл QA на тренажёре с микросервисами, REST/SOAP, Kafka, CI/CD.

  • Сценарии для REST и SOAP API (позитив, негатив, интеграция).
  • Коллекции Postman: окружения, pre/post-scripts, mock server.
  • Kafka: проверка публикации/обработки сообщений, поиск потерь и дублей.
  • Нагрузка в JMeter, рекомендации по порогам алертов.
  • CI в GitHub Actions, UI-автотесты (Cypress) и API-автотесты (Pytest).
  • Мобильное тестирование (учебный проект): push, диплинки, Android Studio, Firebase.

Результат: ручной smoke −60–70%, время проверки API −30–40%, диагностика инцидентов — с часов до десятков минут, онбординг новичков 1–2 недели.
